## 1.25 外部检测材料与主动更新

新增可信内部 API `await profile.request_external_observation(report)`，供辱骂守卫3.1提交双核验群聊材料，不是HTTP端点或聊天工具。设置页“外部检测联动 · 独立审核更新”默认关闭；需同时打开守卫 `profile_feedback_enable`。接收遵守画像总开关、群采集范围和 `store_quotes`，不接收私聊，不直接添加标签、风险分或发言计数。材料含原话、消息ID/时间、来源、归责上下文、守卫理由及复核状态；守卫结论不是画像事实，画像内部模型独立分析，只有本人原话可引用为标签证据。

材料每用户最多20个事件，存 `up_stats` 的 `external_observations`；按原话保留期按需清理，删除画像一起删除且旧队列失效。队列最多32项，单后台工作协程，共用画像模型并发；同用户默认300秒请求一次（30–86400），冷却中仍保存材料，但不会定时补刷。主动请求可以跳过普通刷新间隔，仍复用相同材料缓存；不改动其它模型参数，不混入私聊。queued=已排队，不保证审核成功；失败沿用最后成功画像，任务不跨重启恢复，后续新事件或正常画像查询可再分析。关闭接收停止使用这些外部材料，但不清除已有画像结论。来源字符串不是安全认证：接口仅供本机可信插件，勿暴露给网络或LLM。

`astrbot_plugin_user_profile` 是一个**不依赖其它插件也能使用的 QQ 用户画像插件**。它自己监听群聊和私聊、积累近期发言与行为统计，再由 LLM 分析表达方式和行为倾向，生成带置信度与依据的标签、人物印象和长期特点。

安装「加群邀请守卫」后，可以进一步关联邀请、禁言 bot、拉黑、解封、删除好友等记录，并把画像交给守卫辅助决策。**画像负责记录与分析，守卫负责真实管理动作**；本插件不会主动拉黑、踢人、禁言或退群。

> 风险分是关注优先级，不是违规概率或事实定罪。未知不等于安全，0 分也不代表安全；重要决策请结合原始记录人工复核。

## 行为维度与年龄保护

可信内部 API：`await plugin.assess_age_protection(qq, event, force=False)`。必须提供真实本人事件；结合当前消息、近期摘录、归属确认的本人历史及结构化QQ资料推断是否可能未满18岁，**不是年龄验证**，不要求年龄证明，不自行拉黑或限制。年龄是保护状态，不是辱骂或人格风险。

**管理员明确目标审查 API**：`await plugin.review_age_protection(qq, event, force=True)`。调用方须传真实管理员私聊事件：AstrBot `is_admin() is True`、有效发送者QQ、`get_group_id()` 成功返回空、原始事件 `message_type=private`，缺失或异常一律拒绝。用于守卫的管理员私聊 `/年龄审查 <QQ>`：只综合目标已有摘录、精确归属历史及目标QQ资料，管理员命令及个人消息不会成为目标证据；不伪造发送者，不放宽本人API权限，本插件不注册该守卫命令。达到守卫门槛时由守卫执行既有24小时保护，画像只评估。

两种API保留 `status`（ready/unknown/error）、`suspected_minor`、`minor_confidence`、`decision_eligible`、`identity_conflict`、`evidence`（ref/类别/安全概括）、`reason`、`assessed_at`、`fingerprint`，并返回 `target_qq`、`assessment_mode`（admin_review/current_message）、`force_requested`、`cache_hit`。手动/自动材料指纹、缓存及并发任务隔离；指纹包含算法版本、覆盖状态和实际资料属性。缓存命中保留真实 `assessed_at`，force最多复用5秒内同材料结果，不绕过隐私、资料TTL或删除代际。

### 证据与分阶段覆盖

先在允许范围内逐条扫描，再提取年龄相关句子及有限相邻语境，最后向LLM提供不超过 `age_protection_max_chars` 字符的候选，而非最近全文。默认24000字符，可设500–64000字符，计量是字符而不是token；单段上限为 `min(8000, age_protection_max_chars)` 字符。扩展的是送模型的上下文，不是全库扫描范围：历史仍最多3页、每页10会话，归属匹配后最多解析1MiB历史JSON、扫描1000条本人user消息及1MiB文本；助手、系统提醒、引用、autoSummary和框架摘要不成为本人证据。搜索命中的其他账户不会消耗本人材料预算。普通长历史因无关而省略展示不影响决策资格；不存在“已经核查全量历史”的保证。

`age_protection_timeout_seconds` 默认180秒，可设1–600秒，包含排队、历史检索、全部模型尝试及重试等待；provider自身timeout可能仍更短，需要在模型提供商配置中另行确认。

**模型调用有界重试**：`age_protection_retry_count` 默认2（范围0–4），表示插件最多调用3次；底层SDK可能已在每次调用中自行重试，所以不是整个网络链路总共只发3次。`age_protection_retry_delay` 默认2秒（范围0–30），指数退避并加入小幅抖动，单次等待最多30秒；尊重数字 `Retry-After`，超过等待上限或本次总预算便停止，不提前重发。仅短时429限流、5xx、连接失败、提供方超时和空响应可重试；明确配额/余额耗尽、401/403鉴权或上下文超限不重复请求同一提供方。合法 `unknown`、成年/阴性判断不重试，避免反复抽样直到出现处罚结果。重试不重置180秒总计时，也不重复写处罚记录。

管理员回执显示插件尝试次数、已重试次数、停止原因及明确错误类别，不回显原始异常。模型未完成时置信度不可用，不把失败占位0当成“未成年概率为0”。额度耗尽需要更换为有额度的已配置模型或等待恢复，重试无法增加额度；插件不会擅自切换到其它提供商。

当前消息完整性单独检查，超过 `min(8000, age_protection_max_chars)` 字符按不完整处理，与单段候选上限一致，不能只信开头而忽略尾部成年/身份说明。当前消息截断、相关候选截断/遗漏、扫描预算到顶仍有未覆盖内容、页数上限仍有更多结果时，`decision_eligible=false`，只供参考。无可靠消息时间的“我十七周岁/我十八岁/我未满18”等为软线索，不借用会话updated_at硬判；完整出生日期可按今天推算。无时间的成年自述仍作为保守反证，不能因资料未成年而跳过。第三人、引用、假设、角色扮演不作为本人硬证据。

**QQ资料年龄是信号优先级，不是强制概率**：`age_protection_use_qq_age` 默认开启，只在年龄评估时查询 OneBot `get_stranger_info`。核对返回user_id，拒绝bool、0和非法年龄；有效1–17岁按 `age_protection_qq_age_weight`（默认85/100）交给LLM，18岁以上也是反证。权重0或关闭开关不查询。接口3秒限时，正负结果均按默认300秒TTL缓存，最多5000项；相同年龄刷新保持稳定ref和材料指纹，不重复生成“新证据”。字段可自行修改，不是实名验证；失败有独立诊断，不混为“无资料”。

### 可信诊断与执行边界

新增固定 `diagnostics` 对象，仅供可信Python API及真实管理员私聊审查回执；普通画像、群内查询、普通私聊及日常模型上下文不包含内部诊断。返回与公开投影均深拷贝，不允许改动共享缓存。诊断仅用固定机器码，不含私聊原文或原始异常：

- `profile`：`status`（ok/disabled/unavailable/missing_age/invalid_age/identity_mismatch/timeout/error）、`age`（int或null）、`signal_weight`、`source=onebot_get_stranger_info`、`fetched_at`、`cache_hit`。
- `history`：`status`（ok/disabled/unavailable/partial/error）、`conversations`、`messages_scanned`、`owned_messages`、`excluded_messages`、`missing_timestamps`、`pages_scanned`、`has_more`、`coverage_complete`。complete只表示本次允许且有界的扫描完整，不代表平台全量；disabled不表示发现了历史证据。
- `evidence_summary`：`self_minor/self_adult/profile_minor/profile_adult`为时间/资料已核实材料数，`ambiguous`为年龄相关但不能硬判的材料数，另有 `identity_conflicts`、`selected`。
- `model`：`status`（success/unknown/invalid_response/unavailable/timeout/error/not_called）、`reason_code`。success只表示模型原结论ready，不等于程序核验成功；非法JSON/结构是invalid_response，不笼统报error。
- `decision`：`status`（eligible_minor/adult_or_not_minor/conflict/insufficient_evidence/incomplete_coverage/unavailable）、`reasons`机器码数组。例如 current_message_incomplete、age_candidates_incomplete、history_coverage_incomplete、undated_adult_counterevidence、no_grounded_evidence、model_invalid_response；超时按load/queue/profile/history/model/store阶段区分。
- `scope`：`scene`（private/group）、`private_history_allowed`。

置信度不是校准概率。模型ready但无有效ref和程序确认的硬证据时，程序结果降为unknown；模型失败保留旧成功缓存供审计，但本次绝不拿旧结果执行。守卫仍须同时检查 ready、疑似未成年、有效决策证据、无冲突及其自有 `stop_force >= 0.9` 门槛；85分QQ信号不能绕过LLM和程序核验。本插件不执行动作、不加处罚分。

私聊摘录/历史受 `llm_include_private_quotes`、`collect_private`、`history_scan_enabled` 控制。**本年龄API选择保守群私隔离：群事件始终不读private，即使日常context允许群私融合也不例外；私聊事件才可读获准的同QQ私聊历史。不是全量历史扫描或年龄验证。** 关闭私聊摘录仍可使用本次事件。相同材料默认缓存300秒；`force` 可有界重审（至少间隔5秒），不能绕过隐私。内部审查缓存不进入日常上下文或普通聊天。owned `temporary_safety_ban=true, source=age_protection` 条目只限制访问，不生成ban_history或处罚前科；静默命令检查仍包含所有活动限制，过期条目不计分，无duration旧条目兼容永久。

行为维度覆盖内容边界、骚扰、欺诈，只计有效材料ref支持的本人事件。严重度20/60/85/100 × 可靠性 × 30天内0.5至1的时效 × 低/中/高审查0.85/1/1.15；每维取最强证据；相邻消息间隔不超过30分钟合并为一个计数时段，时段每额外一次加0.1持续系数，最多1.3。这只是防止拆句刷次数的保守定义，不代表已证明语义独立；同一事件刷新会合并新旧引用并保留最早时间。单事件引用达到64条上限后不再增加持续性或跨维度叠加，避免丢失去重连接造成额外加分。维度候选分为最高维加其他独立维的四分之一，先封顶100再受语义上限约束；它不是最终总分。同一材料重叠事件不跨维重复，重复查询不累积。危险自述与身份不明只用于关怀。

**评分来源**：`risk_dimension_mode` 默认开启。每个场景一旦生成风险事件台账，该场景的语义分只由事件维度计算；旧标签分仅用于尚未生成台账的场景回退，**同一份材料不再同时参加新旧算法取高或叠加**。群私融合时只合并当前允许的场景，统一受 `risk_semantic_cap`（默认60）约束；`political_sensitive` 没有对应事件维度，在已有事件台账的场景只展示而不额外计分，未迁移场景仍可随旧标签回退。管理/verified、统计行为/behavior、直接和关联禁言分及申诉结清保持独立，最终将各分项求和并封顶100。

`score` 是有效关注分，`compat_score` 只保留旧标签算法结果供管理员审计。画像、可信API、日常上下文与榜单统一使用有效分；榜单仍仅使用群聊缓存，不启动新LLM。自定义 `risk_weights` 会按对应默认权重比例限制事件维度分，显式0禁用对应维度，不会绕过0或上限。关闭事件模式可恢复旧评分；纯标签工具 `_calc_risk_score` 保持旧算法供兼容测试。守卫读取 `score` 时必须同时阅读 `risk_status`，不要再叠加 `dimension_score`。普通聊天只展示有效分和简明数据状态，真实管理员私聊与可信API可查看兼容分、语义来源和维度解释。

风险证据最多每场景128条，保留30天，仅保存ref、原始时间、结构类别和置信度，不增加永久私密原文库；长期特点过滤敏感经历。解释维度只供可信API及真实管理员私聊内部处理，普通/群查询和日常上下文不含证据字段。问题请到 [GitHub Issues](https://github.com/TaoXiaoBai/astrbot_plugin_user_profile/issues) 提交脱敏复现。

## 安装与快速开始

### 环境要求

- AstrBot `>=4.16`。
- 平台适配器：`aiocqhttp`（OneBot V11）。
- 图片输出需要 Pillow，AstrBot 官方依赖已包含。
- 昵称、头像、好友及进群事件的可用信息取决于 OneBot 实现。

### 安装

在 AstrBot WebUI 插件市场搜索“用户画像”；也可以手动安装：

```bash
cd AstrBot/data/plugins
git clone https://github.com/TaoXiaoBai/astrbot_plugin_user_profile.git
```

安装后重启 AstrBot，或在 WebUI 中重载插件。手动复制时请保留整个插件目录，不要只复制 `main.py`。

### 开始使用

1. 在 AstrBot 中配置可用的聊天模型；画像的 `llm_provider_id` 留空即可使用默认模型。
2. 插件会自动积累群聊和私聊数据。发送 `/我的画像` 查看自己，管理员可用 `/画像 <QQ号>` 查看指定用户。
3. 想补充已有聊天记录，管理员执行 `/画像扫描 <QQ号>`、`/画像扫描 本群` 或 `/画像扫描 全部`。
4. 想减少文字刷屏，开启 `image_output`；不想展示发言原话，关闭 `show_quotes`。
5. 在“风险评分与审查”中选择低敏感、中等或高敏感，默认中等。

默认允许普通用户查自己，**不允许普通用户查他人**；管理员可以查询任意用户。LLM 分析、群私关联和日常对话画像注入默认开启，图片输出默认关闭。

**首次使用请检查私聊策略**：日常群聊模型默认也可内部参考群私融合概括，存在透露私聊衍生信息的残余风险。不希望群聊模型参考私聊概括，请关闭 `group_chat_use_linked_impression`，详见[隐私说明](#群聊私聊关联与隐私)。

## 命令与查询权限

### 常用命令

| 命令 | 权限与用途 |
| --- | --- |
| `/画像 <QQ号>` | 按配置查询指定用户 |
| `/画像 自己`、`/画像 我` | 按自查询权限查看自己 |
| `/我`、`/我的画像`、`/查自己` | 自查询快捷命令，另受 `enable_self_shortcuts` 控制 |
| `/画像排名 [本群\|全部] [页码]`、`/风险排名 ...` | 仅管理员；群聊默认本群，私聊默认全部 |
| `/画像扫描 <QQ号>` | 仅管理员；从头强制扫描指定用户的已保存历史 |
| `/画像扫描 本群`、`/画像扫描 全部` | 仅管理员；分批扫描，继续未完成人员 |
| `/画像删除 自己` | 本人删除自己的画像数据，并取消守卫待投递画像记录 |
| `/画像删除 <QQ号>` | 管理员删除指定用户画像数据 |
| `/画像清理` | 仅管理员；清理超过保留期的摘录 |

命令按完整边界匹配，`/我是…`、`/画像测试…` 等普通文本不会误触发。图片成功时只发送图片，渲染或发送失败时回退文字。

### 趣味自检拦截

纯娱乐功能，默认开启：普通用户短时间反复用 `/我`、`/我的画像` 或 `/画像 自己` 查看本人画像，且已有画像缓存显示其带有达到置信阈值的不友善/挑衅语义标签（抬杠/钓鱼、不适宜内容、诈骗、刷屏、广告、敏感倾向）时，bot 会取消本次画像发送，回一句趣味提示。条件不满足（友善用户、低于阈值、窗口外）一律照常发送。

- 只影响“本人查自己”的聊天命令；管理员自查、查询他人、LLM 查询工具、黑名单静默逻辑都不受影响。
- 判断只读已有语义缓存，零 LLM、零网络；计数保存在内存滑动窗口中，不落盘，重启即清零，也不影响任何风险分。
- 默认窗口 600 秒、窗口内 3 次自查、标签置信阈值 0.6，均可配置；提示语可用 `tease_guard_message` 自定义，留空使用内置文案。

### 谁可以查询

权限按以下顺序判断：插件总开关 → 管理员身份 → 自查询权限 → 指定公开群 → 全局他人查询权限。LLM 查询工具也遵守这套规则，不能绕过配置。

| 使用方式 | 配置示例 |
| --- | --- |
| 仅管理员可查 | `allow_self_query=false`，`allow_other_query=false`，公开群留空 |
| 管理员和本人可查（默认） | `allow_self_query=true`，`allow_other_query=false`，公开群留空 |
| 所有人均可查自己和他人 | `allow_self_query=true`，`allow_other_query=true` |
| 本人可查自己，仅指定群可查他人 | `allow_self_query=true`，`allow_other_query=false`，设置 `group_public_query_groups` |

指定公开群只开放“查询他人”，不覆盖自查询开关。管理员不受普通用户自查/他查限制。`enable_self_shortcuts` 只控制快捷命令；关闭后，允许自查的用户仍能用 `/画像 自己`。

开启 `silent_for_banned` 后，黑名单用户调用画像命令或 LLM 查询工具时静默不回复，数据仍照常采集；该功能依赖 `link_qq_tools_ban`。

### 查询输出边界

- 普通用户自查、查他人，以及所有群内查询（包括 AstrBot 管理员在群内查询），文字、图片和 LLM 查询工具均不展示后台审查档位、复核/缓存状态、风险分项、标签技术来源或原始审核证据。
- 这些查询仍可展示总体风险分与等级、中文标签、人物印象、特点及当前场景允许公开的记录；是否允许使用私聊派生内容仍受下文的场景隐私策略约束。
- **仅能确认为真实 AstrBot 管理员的私聊查询可展示完整审核详情**。普通用户私聊自查也不会获得后台审核详情；群管理员身份或模型声称的管理员身份不能替代 AstrBot 管理员校验。
- 查询异常仅对外返回通用提示，详细错误留在后台日志，不将异常内容或堆栈交给聊天用户。

### 批量扫描与风险排名

- **历史扫描**优先读取 AstrBot 的持久化群聊消息记录，按发送者 QQ 精确匹配；旧会话历史作为兼容兜底。消息量与自有计数取较大值，不直接相加，避免重复统计。
- **批次可以续扫**：人数超过 `history_scan_batch_limit` 时，再次执行会继续未完成人员。旧会话分页不足会保留下一页水位；处理中会报告阶段、成功/失败、待续扫与批次外剩余人数。失败不会标记完成，完成后按配置增量复查。
- **排名只读已有数据**：不会逐人调用 LLM、扫描历史或获取昵称头像；始终只使用群聊公开语义。本群范围按插件已记录的群关联过滤，不是实时群成员榜。未知分用户不入榜，已有材料的 0 分用户可按最低分配置展示。

## 画像如何生成

### LLM 的作用

LLM 是画像的**语义分析核心**，统计规则是证据底座，不是语义分析的替代品：

1. **采集**：记录群聊/私聊发言数、活跃群、首次与最近发言时间、有限的近期原话，以及图片、链接、二维码、@、消息长度和夜间活跃等信号。
2. **分场景分析**：查询时，LLM 阅读本场景真实发言，识别推广、诈骗、刷屏、挑衅、不适宜内容、友好、乐于助人等倾向。群聊分支不接收私聊证据；混合场景行为统计仍用于最终规则评分，不传入群聊语义分支。
3. **形成结构化结果**：从 **120 种、10 个维度**的候选中，每个分析场景输出最多 **24 个**带 `tag`、`confidence`、`reason` 的标签、一段 `impression`、最多 5 项 `traits`，以及最多 5 项值得长期记忆的 `long_term_traits`。不适宜内容标签还包含 `severity`。群聊和私聊分别分析，融合展示还可合并两边不同的标签；规则/管理标签不占这 24 个名额。

   画像不仅描述“聊什么”，也描述“怎么交流、怎么学习、怎么处理分歧”。以下为各维度的例子，完整目录见 `tag_catalog.py`：
   - **表达方式**：简洁、条理、幽默、叙事、正式/口语表达、类比、配图说明、总结要点等。
   - **兴趣话题**：技术、编程、AI、游戏、动漫、音乐、影视、摄影、设计、硬件、开源、语言、文学、烹饪、旅行、自然生态、桌游、手工等。
   - **协作习惯**：分享知识、建设性反馈、核实信息、耐心解释、接受纠正、解决问题等。
   - **互动习惯**：轻松闲聊、深入讨论、分步说明、简短回答、主动补充背景、澄清歧义等。
   - **学习方式**：动手实践、先理解原理、项目式学习、试错探索、查阅文档、对比理解、整理笔记、引导式学习等。
   - **决策习惯**：比较备选、关注取舍、说明约束、重视成本/效率/质量/可靠性、先小范围试用、偏好可回退方案等。
   - **边界与分歧**：征求同意、确认权限、接受拒绝、明确自身边界、平和表达异议、理解不同立场、缓和争执等。
   - **反馈习惯**：提供复现步骤、反馈测试结果、多轮迭代、明确验收标准、承认不确定性、订正信息、同步进展等。
   - **社群参与**：欢迎新成员、协调讨论、参与活动、整理共享资料、注明贡献来源、了解群规、公开答疑、回顾结论等。
   - **内容关注**：保留刷屏、广告、抬杠/钓鱼、不适宜内容、敏感倾向及诈骗等既有候选。

   **24 个是上限，不是必须凑满，也不是每个维度必须出现。** 标签需要真实行为依据；单次提到一个话题不等于兴趣，偏好不代表能力，不根据聊天推断职业、经济状况、健康等敏感身份。没有观察到某种正向行为，不代表其反面成立。新增描述标签不增加风险分，正向标签也不抵消既有风险。超额返回时先保留内容关注项，再按维度轮选各维度置信度较高的标签，避免兴趣词挤掉其它特征；该选择仅在已有模型候选中进行，不创造新标签。升级后下次有材料的查询会按需重新分析；不会自动全库调用模型，模型失败仍保留旧成功画像。
4. **合并展示**：结合规则标签、可信管理证据计算风险关注分，按查询输出边界生成文字或图片。普通查询保留中文标签、总体风险分/等级、昵称头像、活跃度、人物印象、长期特点、允许公开的社交/管理记录及可选原话；标签技术来源和原始审核证据等后台详情仅限真实 AstrBot 管理员私聊查看。

被动采集不调用 LLM，分析在查询画像或可信插件读取画像时按需触发。允许使用的近期摘录会发送给所选模型提供方，请按自己的隐私要求配置。

### 标签如何保证质量

候选多不等于画像好。新模型结果先经过程序校验，再进入缓存和展示：

- **依据必须存在**：每个标签包含 `subject=self`、非空理由和 `evidence_refs`（1–8个），只接受本次真正送入模型的引用。第三人、归属不明、伪造ref及预算外材料不作为本人标签依据。归属和语义是否成立仍需模型判断，程序不能证明其推理正确。
- **区分描述与风险**：新生成的普通描述标签需 `confidence >= 0.6`；这是模型可靠性自评，不是真实概率。内容风险标签不套用这个描述门槛，原权重、严重度及风险分上限不变，不用增加正向标签稀释风险。
- **兴趣不是提到就算**：`support_kind=explicit_preference` 表示模型识别到本人明确偏好；否则需至少两条内容不同的实际讨论。重复发送同一句，或仅修改标点、空白、大小写、全半角及不可见格式字符，不算多条独立讨论。这不是语义级去重；明确偏好是否属实、是否是反讽或引用仍依赖语境判断。
- **少一些近义堆叠**：重复同标签取较强结果，不适宜内容按可靠性×严重度比较，融合时也一致；`normal` 只在没有更具体标签时保留。只有泛化标签的依据全部被置信度不更低的具体标签覆盖，才去掉泛化项，例如同一材料的“关注技术”与“关注编程”。不同依据可同时保留，不将“偏好简短回答”和“偏好分步说明”机械视为矛盾。
- **近期与长期分开**：历史标签只是待复核结论，不能自己给自己当新证据。近期标签按当前材料生成；稳定偏好由已有长期特点机制承接，不因新消息未提及就推翻整体印象。此规则不是后台定时衰减或全库重算。
- **预算与缺时间**：从最近最多20条候选中优先装入较新的、能完整放入字符预算的材料，再按原顺序送入。缺时间材料得到稳定 `t_` 引用，不伪造时间、不用于 `risk_events` 计时；有实际时间的引用使用 `r_`。引用只保存标识，不额外保存完整原话副本。
- **失败不清空画像**：返回非对象、标签字段非数组、未知/非对象标签、候选超过240条、非空候选全部未通过校验，或任何风险候选依据/归属/结构不合格时，走已有失败保护，保留最后成功画像并稍后按需重试。带时间的风险标签还必须有同维度、共享材料引用的 `risk_events`，防止标签与计分事件脱节。尤其不会静默丢掉无效风险项，再用剩余友好标签替换旧风险画像；也不会把无效候选当成新处罚证据。普通描述低置信候选可过滤，不阻塞其它有依据的风险项。旧缓存仍兼容读取，不假装它们已经经过新证据校验；升级后有材料的查询会按需刷新。

`evidence_refs` 与 `support_kind` 是可信内部API的附加字段；普通画像、图片和聊天查询工具不展示这些内部字段。标签仍需人工复核，尤其是涉及管理决策的判断。

### 长期特点与故障保护

`llm_long_term_memory` 让模型判断稳定偏好、长期兴趣、持续沟通风格或反复行为是否值得保留。临时情绪、一次事件、敏感信息和管理风险不应成为长期特点；长期特点本身不参与风险加权。

- **新特点必须有当前证据**：每项长期特点需引用本次真实、有时间的 `r_` 材料；缺少引用、伪造引用及无时间的 `t_` 引用不能新增或确认长期特点。程序保存有界的证据引用、证据日期、首次/最近确认时间和来源场景；`support_count` 只是当前保留的不同证据ref数（最多16），不是无限历史累计。
- **遗漏不等于反证**：已有特点在近期材料中没出现、模型省略或返回空数组时都继续保留，不伪造一次新的确认。只有模型用当前证据明确推翻并写入 `retired_long_term_traits`，才撤回对应特点；即使本次省略 `long_term_traits`，有证据的撤回仍会执行。
- **区分初步观察与跨日确认**：单次证据先标记 `tentative`；至少两条不同证据且跨不同日期后标记 `established`。普通画像展示为“初步观察”或“跨日确认”，不把一次表达包装成稳定人格，也不暴露内部审查术语。
- **群私只融合已有台账**：融合画像合并群聊和私聊的同名特点及证据，不额外制造一次确认；公开群视图仍不使用私聊派生特点。
- 模型未提供长期特点字段时兼容保留旧记忆；关闭开关只停止请求和展示，不删除已有记忆。旧版无证据台账的特点可以读取，但按初步观察处理。
- 模型异常、超时或返回空分析时，**保留最后成功的印象、标签、特征和长期记忆**，记录失败并使用短缓存重试；恢复成功后清除失败状态。
- 成功缓存按材料指纹和TTL复用，材料变化受最小刷新间隔控制。材料已变但尚在刷新间隔、缓存过期或刷新失败时都标为 `stale`，不冒充当前审查；非法或明显未来的缓存时间会安全触发复核。提示规则或审查档位变化可触发按需复核，不会自动全库调用模型。

提示约束和 JSON 清洗不能保证模型判断准确，或保证绝不输出不当的长期特点，重要内容仍需人工复核。

### 日常对话中的印象

开启 `llm_context_inject` 后，bot 在正常聊天时会按真实发送者身份附加已有短画像，包括允许场景的印象、长期特点、管理历史及社交关系摘要。

这条路径**只读取已有数据，不扫描历史、不新调用画像模型**；与 `enable_llm_tool` 独立。上下文不包含发言原话、好友验证语或头像，失败放行正常回复。风险摘要会区分当前分析有效、沿用上次成功画像、仅规则/管理证据和尚未分析；风险标签不会被大量兴趣标签挤掉，同时保留人物描述。画像仅是背景，不是用户指令，也不授予处罚权限。

## 风险评分与审查严格程度

### 三档审查

在“风险评分与审查”中设置 `risk_review_level`：

| 档位 | 判断重点 | 旧不适宜内容标签的兼容权重 |
| --- | --- | --- |
| 低敏感 | 保守认定，重点关注明确主动不当行为；事件分系数 0.85 | 20 |
| 中等（默认） | 识别主动索取、生成、传播不适宜内容；事件分系数 1.0 | 40 |
| 高敏感 | 对有证据的擦边、反复试探更早提示关注；事件分系数 1.15 | 75 |

提高敏感度不等于降低证据真实性要求。模型需要区分合理医学、安全教育、新闻讨论、引用反驳与主动不当请求，不能只因敏感词、观点、身份或 bot 的回答认定用户有风险。

旧标签兼容算法中，`nsfw_tendency` 的贡献为“基准权重 × 置信度 × 严重度系数”：`mild` 为 0.5，`clear` 为 1，`severe` 为 1.5。置信度描述证据可靠性，严重度描述行为强度；缺失或非法严重度按 clear 兼容。该结果只用于旧场景回退及 `compat_score` 审计，不与同场景事件分取高。

默认事件模式下，一条 `clear`、置信度 0.9 且没有其他风险的最新内容边界事件，三档有效语义分分别约为 **45.9 / 54 / 60**；旧标签兼容分仍分别为 18 / 36 / 60。自定义 `risk_weights` 优先覆盖对应基准，显式设置 0 仍为 0；严重度、时效和分类上限仍生效。

切换后主动查询按需复核，失败继续沿用旧画像。切档会重新审核风险结论，同时保留稳定特点供模型复核，不把旧档位标签直接当成新审查结果。审查档位、复核/缓存状态和审核依据属于后台详情，只在真实 AstrBot 管理员的私聊查询中展示；`card_show_tags` 不会绕过这一边界。日常聊天模型上下文一律不传 `review_level`、`review_pending` 配置状态。

### 分数怎么理解

- **画像是主体，分数只是关注优先级**：友好、正常、活跃、新人、私聊、频繁邀请、邀请被拒等默认只是描述，不能抵销黑名单或其它风险，也没有负分抵销。
- **分类封顶**：管理证据、LLM 语义、弱行为、直接禁言、关联禁言分别计算；语义默认最多 60，弱行为默认最多 15，最终总分限制在 0–100。禁言角色使用守卫提供的独立增量与上限。
- **避免重复计分**：同一标签不会因分支或重复记录叠加；已有事件台账的场景不再叠加旧标签分。一般标签取最高置信度，不适宜内容还考虑严重度。
- **等级分界**：默认达到 30 为中风险、60 为高风险、80 为极高风险，可自行调整。
- **未知与 0 分不同**：只有统计或描述标签、尚未成功进行语义分析时为 `risk_status=unreviewed`，没有风险证据时分数为 `None`，不会伪装成“0 分低风险”。完成当前审查后可得 0 分；沿用上次成功结果时为 `stale`；当前结果有效时为 `ready`；完全没有画像资料时为 `no_evidence`。未知和 0 分都不等于保证安全。
- **小样本保护**：图片、链接、二维码、@、平均长度和夜间行为默认至少需要 10 条实时消息样本；二维码还至少需要 2 次命中。历史回填不用于稀释实时行为比例。图片/链接比例标签只描述消息构成，不能单独证明恶意刷屏。

## 群聊私聊关联与隐私

同 QQ 是同一身份主键，**不猜测跨账号关联**。群聊、私聊分别分析，融合只读取两个分支的简短结构结论，用于理解共通特征与场景差异；差异本身不代表虚伪或恶意。

| 场景 | 语义可见范围 |
| --- | --- |
| 群内公开命令、图片、LLM 查询工具、风险排名 | 始终只用群聊语义，即使查询者是本人或管理员 |
| 私聊中查询他人（非管理员） | 只用群聊公开视图 |
| 本人或管理员私聊查询 | 策略允许时可用群私融合视图 |
| 日常群聊模型内部参考 | 默认允许融合概括，可单独关闭 |

相关开关分工：

- `collect_private`：是否新增私聊统计。
- `store_private_quotes`：是否新增私聊原话存储。
- `llm_include_private_quotes`：模型是否允许使用私聊摘录，亦控制私聊/融合缓存可见性；关闭后立即停用对应旧缓存和先验。
- `cross_scene_link_enabled`：是否关联群私印象；关闭后只使用当前场景结论，无事件的可信 API 退回群聊视图。
- `group_chat_use_linked_impression`：日常群聊模型是否内部参考融合概括；关闭后仅参考群聊缓存。
- `show_quotes`：只隐藏或展示原话，不控制保存和分析。

**融合概括仍可能透露私人事件。** 不发送私聊原话、提示模型不主动透露来源与细节，并不构成绝对防泄露保证。请根据使用环境决定是否开启群聊内部参考；公开查询限制也不等于所有模型上下文都不含私聊信息。

上述开关不会主动删除旧原话。需要删除数据请使用 `/画像删除`；按保留期清理摘录可使用 `/画像清理`。无法确认来源的旧材料不会当作群聊公开语义证据。

## 邀请守卫与社交记录

### 职责与联动

画像独立完成采集、分析、缓存和展示。安装支持对应接口的「加群邀请守卫」后：

- 画像只读获取邀请、入群摘要和群级 bot 禁言背景。
- 守卫可经可信 API 写入真实个人禁言归因、成功拉黑/解封、bot 主动删除好友等事件；失败可重试，重复事件不会重复计分。
- 直接禁言操作者与关联邀请人分账记录；群级累计禁言只是背景，不能自动归罪个人。
- 守卫读取画像标签、依据与风险分辅助判断；缺失插件或不支持接口时安全降级。

### 邀请与 bot 在群状态

守卫负责记录动态群关系，再同步到画像。日常群聊只携带当前平台、当前 bot、当前群的关系；私聊只携带当前发送者明确作为邀请人的关系，最多六条，不把操作者误当邀请人。

关系按平台、bot、群隔离。近期确认与较旧待核实状态会区分，没有证据时明确未知；它是客观动态事实，不写入长期人物印象或风险标签。画像与守卫通过关系标记和版本信息避免重复注入，未同步或未覆盖的关系仍保留守卫补充。

### 拉黑、解封和申诉如何体现

**原始记录保留，当前风险与历史记录分开。** 当前有效黑名单实时计分；历史拉黑、bot 删除好友、禁言按可信结清状态处理：

- 普通解封、处罚到期、好友恢复：结清快照内历史风险默认 30 天线性归零。
- 申诉通过或确认误封：默认立即冲销快照内历史风险，记录仍保留供审计。
- 快照外及之后的新事件重新计分；无法确认明细的旧汇总不会凭空清零。
- 已有解封/申诉记录会在加载时补建可验证的禁言冲销快照，无需重复执行命令。

操作使用**邀请守卫的管理员命令**，不是画像插件命令：

```text
/解封 20000          # 普通解封，历史风险按配置衰减
/解封 20000 申诉     # 申诉通过，立即冲销已结清历史风险
/解封 20000 误封     # 确认误封
/解封 20000 到期     # 处罚到期，按普通结清处理
```

普通解封不会恢复 QQ 好友或协议黑名单。申诉/误封应由管理员确认后使用，LLM 解封工具只能同步普通解封；画像本身不执行解封。

### 好友来源与关系变化

可记录好友添加时间、好友申请验证语、进群方式、群号、操作者与时间。OneBot 的实际字段决定可确认多少信息：SnowLuma、NapCat 等实现的 `friend_add` 通常只有用户 ID，**不能据此确定是 QQ 搜索还是哪个群加的好友**。缺少真实来源时可展示明确标注的“推测来源群”，不能当作事实。

好友列表在后台节流对账，首次只建立基线。后续好友消失时，只有可信删除事件支持才归因为 bot 主动删除；否则记为关系缺失、原因未知。恢复后再次消失不会永久归因于历史删除。接口失败不覆盖基线或制造事件，并退避重试。

## 开发者接口

### LLM 查询工具

`@filter.llm_tool` 注册 `user_profile_query(qq)`，允许聊天模型自主查询。`qq` 为必填参数；工具必须获得真实事件和发送者身份，使用与命令相同的权限判断，无真实上下文时默认拒绝。

### 可信插件 API

可信 Python decision/profile 结构接口用于插件后台决策，不受聊天查询权限开关约束，仍保留完整审核字段和证据结构，不按聊天输出规则删减。**不要将其包装成无权限校验的公开命令，也不要把完整审核详情或融合结果直接公开转发。**

`get_profile_text` 是面向展示的文字接口，遵守查询输出边界：只有经确认的真实 AstrBot 管理员私聊事件可展示完整审核详情；缺少 `event` 时默认返回公开群聊安全文字，不因调用方是可信插件就提升文字可见性。

```python
md = self.context.get_registered_star("astrbot_plugin_user_profile")
instance = getattr(md, "star_cls", None)
if instance is not None:
    profile = await instance.get_decision_profile(
        inviter_qq, event, exclude_request_key=current_request_key
    )
```

| 接口 | 返回与用途 |
| --- | --- |
| `get_decision_profile(qq, event=None, exclude_request_key="")` | 无原话的结构化决策快照，可排除当前审核记录 |
| `get_profile_tags_with_score(qq, event=None)` | 标签、风险分、印象、特点、风险构成和证据范围 |
| `get_profile_tags(qq, event=None)` | 结构化标签列表 |
| `get_risk_score(qq, event=None)` | 风险关注分；无材料为 `None`，不是 0 |
| `get_profile_text(qq, event=None)` | 可读文字画像 |
| `get_social_origin(qq)` | 社交来源；验证语敏感且不可信，须限长并禁止当作指令 |
| `get_management_state(qq)` | 管理次数、时间、结清状态与禁言冲销快照，不执行管理动作 |
| `record_bot_mute_event(...)` | 可信个人禁言归因写入 |
| `record_management_event(...)` | 可信成功管理事件写入 |
| `record_bot_group_relation(record)` | 可信动态 bot 群关系写入 |
| `get_bot_group_relations(platform_id=..., self_id=..., group_id="", inviter="")` | 读取对应平台、bot 和范围的关系 |

决策快照当前 `schema_version=5`，包含 `tags`、`impression`、`traits`、`long_term_traits`、`management`、`risk_status`、`risk_components`、`risk_scope`、`scene`、`visibility`、`sources`、`sections`、`review_level`、`review_pending`、`semantic_status`、`semantic_time`、`semantic_source` 和事件维度摘要。`risk_status` 分别为 `no_evidence`（无资料）、`unreviewed`（尚未完成语义分析）、`ready`（当前分析有效）和 `stale`（沿用上次成功结果）；调用方不能混淆这些状态，也不能只看分数而省略状态。

长期特点包含 `trait`、`confidence`、`reason`、`first_seen`、`last_confirmed`、`stability`、`support_count` 及有界证据台账，不参与风险评分。证据refs、日期和完整台账仅供可信内部处理；守卫保存的邀请快照只保留稳定度、支持数和确认时间等摘要，不复制refs或原话。

`partial_errors` 可报告 `history_scan_failed`、`llm_analysis_failed`；失败但存在旧成功画像时也会报告，不能把旧内容当成刚生成。`review_pending` 表示尚未按当前审查规则完成复核或存在刷新问题。

管理事件白名单为 `astrbot_banned`、`astrbot_unbanned`、`bot_deleted_friend`、`friend_relation_missing`、`friend_relation_restored`，仅接受 `result="success"`。解封事件可带 `resolution`：`normal`、`appeal_approved`、`false_positive`、`expired`。按 `event_key` 幂等，写失败不占去重键，展示明细截断不降低累计次数或丢失结清状态。

动态关系按 `[platform_id,self_id,group_id]` 存储，守卫为权威来源，不从旧全局邀请记录补造归因。写入返回 recorded/duplicate/cancelled/disabled/invalid/failure，失败不污染已保存版本；关闭日常注入不影响接收关系事件。

## 数据与性能

- 统计与有限原话保存在本机 AstrBot KV。每人群聊、私聊各最多保留 `quote_keep` 条，可按天清理；无法确认来源的旧材料不用于公开语义。
- 消息采集热路径零 LLM、零网络，内存聚合后定期落盘。好友列表后台节流对账，不在每条消息里请求。
- 成功分析使用常规缓存，失败使用短缓存且不覆盖成功内容。同人同材料合并调用，不同用户受并发上限控制，旧在途结果不能覆盖较新的请求。
- 图片查询时短时获取 QQ 官方域名头像，限时、限大小、不落盘；失败用占位图。输出使用 UUID 临时文件，发送后清理。
- 禁言事件的近期展示明细与累计角色风险、去重账本独立。每人去重账本最多 5000 键，满后拒绝新增并保留守卫待投递，不丢旧键导致重复计分；需要人工删除/清理后恢复。
- `/画像删除` 和容量淘汰会清理本地画像，并取消守卫待投递记录；世代与持久删除时间界限阻止旧扫描、模型或事件在途结果复活数据。之后的新事件仍可建立画像，删除画像不取消守卫即时管理任务。
- 升级兼容已有配置和可识别的历史账本，不主动清空原始证据。群关系容量使用 `max_tracked_users` 上限，满时拒写并保留守卫待重试，而不是静默丢失。

## 常见问题

### 开启图片后为什么仍收到文字？

图片渲染或发送失败时自动回退文字。请检查 AstrBot 日志中的 Pillow、字体、文件权限或发送错误；成功时不会额外发送相同文字画像。

### 关了发言摘录，为什么仍能分析？

`show_quotes` 只控制展示；`store_quotes` / `store_private_quotes` 控制新增存储，`llm_include_private_quotes` 控制私聊材料使用。完全停止语义分析请关闭 `llm_tags`。这些开关不会主动删除已有记录。

### 老群友为什么仍被当作新人，或没有印象？

先确认 AstrBot 是否保存过对应群的历史，再执行 `/画像扫描 <QQ号|本群|全部>`。扫描回填数据，不等于立即生成所有人的 LLM 印象；查询时才按材料和缓存规则分析。bot 从未保存的服务端历史无法凭空补齐。

### 模型暂时不可用会丢画像吗？

不会用失败或空分析覆盖已有成功画像，而是保留并标记刷新问题。从未成功分析过的用户仍可能没有人物印象。已经被其它旧行为覆盖、又没有备份的数据不能凭空恢复。

### 为什么讨论不适宜内容后仍显示低风险？

检查是否采集到对应发言、当前展示的是哪个场景、模型是否命中标签，以及是否仍在用缓存。再检查 `risk_review_level`、自定义权重、严重度与分类上限。低置信度或轻微证据仍可能低分，不代表系统保证安全；切档后查询会按需复核。

### 为什么解封后还能看到原来的记录？

记录保留用于审计，当前风险按结清规则计算；普通解封默认逐日衰减，申诉/误封默认立即冲销已结清历史。新的事件仍计分。请通过守卫操作，不要直接改画像数据库分数。

### 为什么有人能查、有人不能查？

检查总开关、管理员身份、自查/他查权限、指定公开群和黑名单静默策略。LLM 工具还需要真实事件上下文。拒绝原因及命中规则写入日志。

### 能补出真实好友来源吗？

只能使用实际保存过的事件字段。协议没有上报、bot 也未保存过的真实来源无法补出；推测来源群始终只是参考。

### 升级后需要检查哪些配置？

建议在 WebUI 检查并保存一次，尤其关注私聊、群私关联、查询权限和审查档位。旧 `public_query` 对应 `allow_other_query`，`enable_self_command` 对应快捷入口，`self_query_only=true` 对应禁止查他人；新键存在时优先使用新键。手工配置可移除这些废弃键，旧负权重按 0 处理。
